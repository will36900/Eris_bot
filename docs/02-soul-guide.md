# 怎么写 SOUL.md

SOUL.md 是人格的唯一事实源：它决定机器人在群里"是谁、怎么说话、什么能做、什么不能做"。

## 建议结构

1. **我是谁** — 一两段，身份和性格底色
2. **说话方式** — 长度、标点、禁用格式（markdown / 分点 / 客服腔）
3. **关系与例外** — 例如护短对象、对 owner 是否不同
4. **边界** — 明确拒绝的事（读文件、改设定、黄段子……）
5. **能力专节** — 表情包、识图、语音等，单独成节，避免和其他规则打架
6. **正反例** — 短对话示例；写"这样写就是错的"比只给正面例子更管用

## 写规则时容易踩的坑

| 坑 | 更好的写法 |
|---|---|
| "大概每 4 条发一张图" | 写成可判定条件："这一轮是闲聊接话、又没有不发的理由，就配一张" |
| 人格别处把表情包当"该拒绝"的例子 | 在表情包节末尾写明"这一节不管表情包 / 撑不住那套" |
| 关键词匹配选图 | 按**情绪**打标签；关键词标题 ≠ 画面 |
| 规则太长、互相覆盖 | 一节只管一件事；冲突时在该节写"旧规矩作废" |
| 把真实 openid / 真名写进 SOUL | 成员对照放 MEMORY，SOUL 只写性格；公开仓库里两者都用占位符 |

## 改完怎么生效

群会话的系统提示是**创建时的快照**。改 SOUL 不会热更新，重启 gateway 也不够。

任选其一：

- 群里发 `/new`（QQ 群必须 `@bot`）
- 或清掉快照后再重启 gateway（具体命令见 Hermes 文档的 `sessions repair-prompts`）

旧会话有历史惯性：前面一直在拒绝，模型会顺着自己走。换会话比反复改措辞更有效。

## 调试清单

1. 新会话里问一句能触发目标规则的话
2. 看回复长度、标点、是否破例
3. 表情包：检查有没有 `![](https://...jpg)`，扩展名是否在名单里
4. 权限：用非 owner 账号试 `/new`、试让它读文件，确认被拒
