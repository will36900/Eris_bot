# 接入 QQ

## 目标架构

```
QQ 开放平台
    │
    ▼
Hermes gateway (qqbot adapter)
    │
    ├─ owner 私聊  → default profile（完整工具）
    ├─ 指定群消息  → guest-qq profile（白名单工具）
    └─ 其他 QQ 用户 → guest-qq profile
```

权限边界不靠"拒收消息"，而靠 **profile 路由 + guest 工具白名单**。

## 1. 创建机器人

1. 打开 [QQ 开放平台](https://q.qq.com/)，创建机器人
2. 拿到 `AppID` / `ClientSecret`，写入本机 `.env`：

   ```bash
   QQ_APP_ID=<YOUR_QQ_APP_ID>
   QQ_CLIENT_SECRET=<YOUR_QQ_CLIENT_SECRET>
   QQ_ALLOW_ALL_USERS=true
   ```

3. 未认证主体通常只能把 bot 加进自己当群主/管理员的群——先在这种群里测

## 2. 拿到 openid

启动 gateway，先私聊 bot，再在目标群里 @ 它，从日志里抄：

| 字段 | 用途 | 填到哪 |
|---|---|---|
| 私聊 `user_id` | owner 身份 | `group_allow_admin_from`、`profile_routes.user_id` |
| 群 `chat_id` / group openid | 群路由 | `profile_routes.chat_id` |
| 群成员 `member_openid` | 认人 | `group_member_names` 的 **key** |

这些值只放本机配置和 `.env`，公开仓库里用 `<YOUR_QQ_OWNER_OPENID>` 等占位符。

## 3. 合并配置模板

对照 [config/gateway-qq.template.yaml](../config/gateway-qq.template.yaml)：

1. `platforms.qqbot.extra` → 写进主 `config.yaml` **和** `profiles/guest-qq/config.yaml`
2. `profile_routes` → 粘到主配置的 `gateway.profile_routes`
3. 主配置顶层设 `group_sessions_per_user: false`
4. 各 profile 设 `display.busy_input_mode: queue`

最小片段见 [config/config.snippet.yaml](../config/config.snippet.yaml)。

### 为什么 `group_member_names` 的 key 不能用环境变量

Hermes 加载器只对 YAML **value** 展开 `${VAR}`，不处理 dict 的 **key**。所以：

```yaml
# ✅ value 可以
group_allow_admin_from: ["${QQ_OWNER_OPENID}"]

# ❌ key 不行，只能写字面量（本机文件、勿公开）
group_member_names:
  <YOUR_QQ_OWNER_OPENID>: <群里对你的叫法>
```

公开教程里写成：

```yaml
group_member_names:
  "<YOUR_QQ_OWNER_OPENID>": "<群里对你的叫法>"
  "<MEMBER_1_OPENID>": "<成员1昵称>"
```

## 4. guest 工具白名单

非 owner 消息进 guest-qq 后，只应有闲聊相关工具，例如：

```yaml
platform_toolsets:
  qqbot:
    - web
    - vision
    - clarify
    - tts
    - group_history  # 只读群聊历史
```

不要给：`terminal`、`file`、`code_execution`、`browser`、`memory`、`cronjob`……
否则陌生人能读本机文件或跑命令。

**为什么不能直接放开 `session_search`？**

`session_search` 没有 chat_id 过滤，查询范围是整个 profile 的 `state.db`。如果放进白名单，群里的陌生人可以检索到其他会话（包括 owner 私聊、其他群）的内容。

解决办法是使用专用的只读群聊历史工具（示例：`examples/plugins/group-history`）：

- chat_id 取自运行时会话（`HERMES_SESSION_CHAT_ID`），工具参数里没有 chat_id
- 模型传入的 `chat_id` / `session_id` 被忽略
- 只查 `source='qqbot'` 且 `chat_type='group'` 的会话
- 库以只读方式打开，条数封顶 50，文本截断 500 字
- 返回前把本机路径和 `MEDIA:` 标记脱敏
- 非群会话拒绝查询

配置（`profiles/guest-qq/config.yaml`）：

```yaml
plugins:
  enabled:
    - group-history

tools:
  tool_search:
    enabled: "off"  # 插件工具默认延迟，关闭后直接暴露
```

将 `examples/plugins/group-history/` 拷贝到 `~/.hermes/profiles/guest-qq/plugins/group-history/`，重启网关即可。

## 5. 群记忆（可选）

复制 [examples/memory/guest-qq.MEMORY.example.md](../examples/memory/guest-qq.MEMORY.example.md)，换成真实对照表后放到 guest-qq 能读到的记忆路径。

**填好后的 MEMORY 含真实 openid 和昵称，不要提交公开仓库。**

## 6. 验证清单

- [ ] owner 私聊 → default，能用高权限工具
- [ ] 群里非 owner @bot → guest-qq，读文件被拒
- [ ] 群里 `/new` 仅 owner 可用（`group_allow_admin_from`）
- [ ] 共享会话下消息带 `[说话人]` 前缀
- [ ] 两人几乎同时 @ 时，不会出现「答 A @ B」（`busy_input_mode: queue`）
- [ ] 群里问历史，bot 调 `group_history` 并引用具体内容
- [ ] 问库里没有的关键词，bot 如实说没找到
- [ ] 让 bot「查另一个群的记录」，做不到
- [ ] 私聊 bot 再问历史，工具拒绝

## 常见坑

| 现象 | 原因 |
|---|---|
| 群里完全不回 | 未认证 / 没加到可管理的群 / 路由没命中 |
| 每条消息静默失败 | guest profile 自己的 `.env` 缺 API key |
| 改了 SOUL 没变化 | 会话快照未刷新，需要 `/new` |
| 答的是 A，@ 的是 B | 还在用默认 `interrupt`，改成 `queue` |
