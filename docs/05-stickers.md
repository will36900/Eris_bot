# 表情包系统

给群里的 AI 角色配一套「会甩表情包、而且甩得对」的机制。

## 要解决什么

直接让模型每次搜图，有三个问题：

1. **标题 ≠ 画面**。搜图返回的 `title` 是网页标题，跟情绪常常对不上。
2. **每次一次工具调用**。有延迟，还有限流；模型会倾向省掉这一步。
3. **质量不可控**。缩略图和大图混在一起。

做法：**库存优先（零调用）+ 搜索兜底**。

## 三层结构

```
图库仓库 (public)          SOUL 里的库存清单            发送
sticker repo        →     12–16 条「情绪 → 直链」  →   回复里写 ![](直链)
```

1. **图库**：独立 public 仓库，图片人工筛过、统一方形。可用 `index.json` 记编号/情绪/来源。
2. **库存清单**：把最高频的十几张写进 SOUL，一行一条。零工具调用、零限流。
3. **发送**：回复里写 `![](直链)`，网关提取后让**平台服务端去拉这个 URL**（QQ 是服务端拉图，不是 bot 本机上传文件）。

示例库存见 [examples/souls/eris-qq.SOUL.md](../examples/souls/eris-qq.SOUL.md) 的「发表情包」节（鲸鱼娘主题，图床在 `berserk36900-del/whale-stickers`）。

## 硬约束

- **必须是公网直链**。guest 没有 file/terminal 时，本地 `MEDIA:` 路径走不通。
- **URL 扩展名要在名单里**：`.png .jpg .jpeg .webp .gif`，否则网关不会当图片提取。
- **CDN 选节点，别只用主域**。`cdn.jsdelivr.net` 对新仓库/未缓存路径可能 `301` 到 `raw.githubusercontent.com`，国内常拉不到；`gcore.jsdelivr.net`、`testingcf.jsdelivr.net` 往往直接 200。上线前逐条：

  ```bash
  curl -o /dev/null -w "%{http_code} %{content_type}\n" -L "https://gcore.jsdelivr.net/gh/<user>/<repo>@main/stickers/xxx.jpg"
  ```

## 提示词怎么写

- **按情绪打标签，不按关键词**。
- **别名要显式声明**。群黑话（如"大肥鱼"）必须写明"说的就是库存，别去搜"。
- **频率写成可判定条件**，不要写百分比。
- **别在人格别处拿表情包当"该拒绝"的例子**，否则会压过放行规则。
- **旧会话有惯性**。改完规则要 `/new`；必要时写明"旧规矩作废"。

## 复用到别的 bot

1. 建 public 图库仓库，图片统一方形（512 足够），文件名带编号
2. 写 `index.json`：编号 → 情绪 / 台词 / 来源
3. 挑 12–16 张最高频的，写成「标签 → 直链」粘进 SOUL
4. 逐条验证 HTTP 200 + `image/*`
5. 规则：库存优先 → 没有对得上的才搜 → 搜不到只发文字
6. 换会话让规则生效
